# Artifact: v2 data and table scripts

This folder holds the data and the table script behind the paper *Rollback Is
Not Recovery: Decomposing Recovery Time in a Native GitOps Stack with Argo
Rollouts and Argo CD*. The framework that produced the data (cluster setup,
manifests, scenarios, trial runner and extractor) is the rest of this
repository.

## Layout

| Path | Size | Content |
|---|---|---|
| `data/all-trials.csv` | 224 KB | one row per trial (247 rows), all extracted fields |
| `data/summary-by-condition.csv` | 12 KB | one row per cell: counts, means, spread, precision check |
| `data/components-by-condition.csv` | 8 KB | mean recovery components per cell |
| `data/conditions/*.csv` | 352 KB | the rows of `all-trials.csv` split by strategy, scenario and sync policy |
| `data/bluegreen-tick-delay.csv` | 2 KB | abort ticks of the 26 analysis-detected blue-green trials (see below) |
| `data/plan.json` | 52 KB | the run plan: seed, cells and the randomised trial order (238 planned trials) |
| `data/trials.tar.gz` | 7.3 MB | the raw record of the 247 trials, one directory per trial |
| `logs/run-session1.log`, `logs/run-session2.log`, `logs/run-reruns.log` | 130 KB | runner console logs |
| `paper-tables/make_tables.py` | 20 KB | generates the paper's Tables II–IV and its in-text numbers |
| `paper-tables/design.tex` | 4 KB | Table I (written by hand) |

Each trial directory in `trials.tar.gz` contains `events.jsonl` (every observed
change of the Rollout, AnalysisRun, ReplicaSet, Pod and Application objects,
with host timestamps), `requests.csv` (the load generator's request log),
`actions.json` (the runner's actions), `meta.json` (trial settings and
covariates) and `row.json` (the extracted row).

## What the data contain

- **Invalid trials are kept.** `all-trials.csv` has all 247 trials (238
  planned plus 9 re-runs). The column `valid` marks which ones count; the
  table script uses only valid trials (231). Rolling trials of the history
  block never reached their precondition and are all invalid.
- **Control cells.** The two stable-pod control cells
  (`control-stable-crash`, `control-stable-partition`; 7 valid trials each)
  are in the data and in the counts, but the paper does not report their
  results.
- **Censored trials.** A trial that did not recover before its scenario's
  timeout has `censored = True`; its recovery times are empty.

## Blue-green tick file

`data/bluegreen-tick-delay.csv` has one row for each of the 26 analysis-detected
blue-green trials. It is generated by `paper-tables/bluegreen_ticks.py` from the
trials' AnalysisRun events (in `trials.tar.gz`) and the Prometheus scrape
timestamps that the extractor recorded in `all-trials.csv` (`scrapes_app`,
`scrapes_ksm`) during the run. It counts the analysis measurements with the
functions in `runner/mttr/model.py`. Prometheus itself is not needed. Times are
seconds after `t_inject`.

| Column | Meaning |
|---|---|
| `trial_id`, `scenario`, `sync`, `revert` | the trial and its cell |
| `abort_s` | observed abort time (`rollback_trigger_latency_s`) |
| `tick_two_release_scrapes_s` | the analysis tick at which the error-rate metric fails for the second time if two faulty scrapes of any preview pods are enough |
| `delayed_one_tick` | the observed abort came one 15 s tick after `tick_two_release_scrapes_s` |

`tick_two_release_scrapes_s` is empty for crash-loop trials, which were
detected by the restart metric rather than by the error rate.

To regenerate it:

```bash
mkdir -p artifact/data/trials
tar -xzf artifact/data/trials.tar.gz -C artifact/data/trials
cd artifact/paper-tables
../../.venv/bin/python bluegreen_ticks.py
```

## Reproduce the tables

```bash
python3 -m venv .venv
.venv/bin/pip install pandas==2.3.1
cd artifact/paper-tables
OUT_DIR=out ../../.venv/bin/python make_tables.py
```

This writes `out/breakdown.tex`, `out/impact.tex`, `out/coverage.tex` and
`out/numbers.tex` (the `\m...` macros used in the text) from
`../data/all-trials.csv`, `../data/summary-by-condition.csv` and
`../data/bluegreen-tick-delay.csv`. Set
`RESULTS_DIR` to read another data directory.

## Re-extract the CSV from the raw trials (optional)

```bash
mkdir -p artifact/data/trials
tar -xzf artifact/data/trials.tar.gz -C artifact/data/trials
pip install -r runner/requirements.txt
cd runner
RESULTS_DIR=../artifact/data python -m mttr extract --no-prometheus
```

This overwrites `artifact/data/all-trials.csv` and `artifact/data/conditions/`,
so work on a copy. Without Prometheus it reproduces every column except the ten
Prometheus cross-check columns (`prom_*`, `scrapes_*`, `xcheck_*`); those were
read from the live Prometheus during the run and are kept only in the shipped
`all-trials.csv`. The table script needs them, so generate tables from the
shipped file.

## Column dictionary: `all-trials.csv`

Times named `t_*` are Unix timestamps in seconds (host clock); fields ending in
`_s` are durations in seconds, measured from `t_inject` unless stated. Empty
means not applicable (for example, no rollback happened) or censored.

| Column | Meaning |
|---|---|
| `trial_id` | trial name; `r1` suffix = re-run of an invalid trial |
| `strategy` | `canary`, `bluegreen` or `rolling` |
| `scenario` | fault scenario (directory name under `scenarios/`) |
| `sync_policy` | Argo CD sync policy: `auto` or `manual` |
| `revert_path` | how the operator's revert reaches Argo CD: `webhook` or `poll` |
| `block` | design block: `core`, `revert-path`, `drift`, `control-path`, `history`, `baselines` (the two stable-pod control cells) |
| `order`, `rep`, `attempt` | position in the randomised plan, replicate number, attempt number |
| `inject_kind` | how the fault was injected: `git-commit`, `chaos-mesh` or `kubectl-patch` (drift) |
| `v1_hash`, `v2_hash` | pod-template hashes of the stable and the new release |
| `release_is_healthy` | the new release carries no fault (control-path healthy cells) |
| `history_precondition` | the history precondition was present before the fault |
| `confirmed` | the fault was confirmed to take effect |
| `baseline_success` | request success ratio in the baseline window before the fault |
| `valid` | the trial counts (baseline ≥ 99.5 %, fault confirmed, precondition present) |
| `censored` | no recovery before the scenario's timeout |
| `t_inject`, `inject_lag_s` | fault arrival; time from the runner's action to the fault taking effect |
| `t_abort`, `rollback_triggered`, `trigger_cause` | rollout abort time; whether an abort happened; `analysis`, `deadline` or `none` |
| `rollback_trigger_latency_s` | detection: fault arrival to abort |
| `t_analysis_start`, `analysis_start_offset_s`, `analysis_ticks` | start of the AnalysisRun; its offset from the fault; measurement times (JSON) |
| `first_failing_measurement_s` | time of the first failing analysis measurement |
| `failed_metric` | analysis metric(s) that failed or errored |
| `t_rollback_done`, `rollback_execution_s` | end of the rollback; abort to end of rollback |
| `release_scaled_down_s` | abort to the new release's ReplicaSet reaching 0 replicas |
| `service_impact`, `bad_bins` | whether any 1 s window was unhealthy; number of unhealthy windows |
| `t_service_restored`, `mttr_service_s` | service end point and MTTR_service |
| `mttr_service_all_failures_s` | the same, counting failures from any release |
| `failed_requests` | failed requests answered by the faulty release (or by no pod) |
| `background_failed_requests` | failed requests answered by other pods |
| `requests_served_by_release` | requests answered by the faulty release |
| `requests_in_outage` | requests between the fault and service restoration |
| `t_first_fault_response`, `first_fault_response_s` | first faulty response from the new release |
| `first_release_restart_s` | first container restart in the new release |
| `p95_latency_ms_baseline` | 95th-percentile request latency in the baseline window (ms) |
| `t_operator_sees_failure`, `t_revert_commit`, `t_operator_sync` | operator alert, revert commit, manual sync request |
| `t_outofsync`, `outofsync_lag_s` | Argo CD reports OutOfSync; revert commit to OutOfSync |
| `t_sync_started`, `t_synced`, `sync_duration_s` | Argo CD sync start and end; its duration |
| `argocd_state_before_revert`, `argocd_syncs_between_abort_and_revert` | Argo CD sync/health state just before the revert; syncs between abort and revert |
| `t_state_converged`, `t_full`, `mttr_full_s` | convergence to the Git head (Synced, Healthy, baseline stable and Ready); full end point and MTTR_full |
| `t_cleanup_done`, `cleanup_after_converged_s`, `mttr_full_strict_s` | old ReplicaSets scaled down; its time after convergence; MTTR_full under that stricter definition |
| `comp_detection_s`, `comp_rollback_s`, `comp_operator_wait_s`, `comp_reconcile_s` | recovery components: detection, rollback execution, operator wait, reconciliation |
| `comp_service_after_rollback_s` | end of rollback to service restoration |
| `rollback_success`, `recovered_by`, `coverage_class` | whether the rollback restored service; layer that recovered (`rollouts`, `argocd`, `kubernetes`, `operator+argocd`, `none`); class (`analysis`, `deadline`, `self-heal`, `operator-only`, `tolerated`, `stalled`) |
| `max_clock_skew_ms` | largest clock offset between nodes (chrony) |
| `host_*`, `grl-*_cpu_m`, `grl-*_mem_mib`, `release_pod_nodes` | covariates: host memory, swap, load; node CPU and memory use; nodes of the release pods |
| `prom_t_*`, `scrapes_app`, `scrapes_ksm`, `xcheck_*` | Prometheus cross-check: the same events as seen in Prometheus, scrape counts, and their offsets from object status |

## Column dictionary: `summary-by-condition.csv`

One row per cell (scenario, strategy, sync, revert); statistics over valid,
uncensored trials, in seconds.

| Column | Meaning |
|---|---|
| `n`, `censored` | valid uncensored trials; censored trials |
| `MTTR_full mean`, `median`, `SD`, `CV`, `P95` | MTTR_full statistics |
| `MTTR_full strict mean` | mean MTTR_full under the stricter convergence definition |
| `MTTR_service mean`, `svc SD` | MTTR_service mean and standard deviation |
| `trigger mean`, `trigger CV` | detection (fault to abort) mean and coefficient of variation |
| `cause` | what triggered the abort |
| `rollback ok`, `success CI` | successful rollbacks / rollbacks; Wilson 95 % interval |
| `CI half-width`, `precision met` | half-width of the 95 % CI of mean MTTR_full; whether it is at most max(10 % of the mean, 10 s) |
| `N required` | trials per cell that this half-width would need |
